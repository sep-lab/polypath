# VPN V2 — Project Context for Claude

This file provides context to Claude Code and other AI assistants working on this project.

## What This Project Is

A censorship-resistant VPN infrastructure designed for users in Iran. It provides multiple independent paths to bypass DPI (Deep Packet Inspection) using protocol diversity across 4 servers.

## Architecture Summary

- **4 VPN servers**: Helsinki (Hetzner), Madrid (Oracle), Dammam (GCP), London (Scaleway)
- **15+ protocol types**: VLESS Reality, Hysteria2, XHTTP-CDN, CDN-WS, XrayHTTP, SS2022, Finalmask (XDNS/XICMP), ShadowTLS v3, NaiveProxy, Cloak+SS2022, DNS Tunnel, Hy2 Salamander, EDtunnel, MTProto, AmneziaWG
- **Multi-CDN**: Cloudflare + Vercel relay + Netlify relay
- **Smart-sub worker v5.11+**: Cloudflare Pages function (TypeScript source in `tools/smart-sub/src/`, bundled to `worker.js`) that generates **~144 VPN configs**
- **Primary domain**: `sub.example.com` → CF Pages project `your-pages-project`
- **Backup domain**: `sub.example.net` → Vercel Edge Functions project `backup-sub`
- **Geo-aware**: Iran users get CDN-only + TLS fragment + MUX padding + ISP-specific tuning
- **All traffic routes through HAProxy on port 443** on each server

## Worker Source Structure (TypeScript)

The smart-sub worker source lives in `tools/smart-sub/src/` (TypeScript modules):

- **`index.ts`** — Entry point, request handler, subscription builder loop
- **`config.ts`** — `buildConfig(env)`: server definitions, user accounts, edtunnel/relay config
- **`generators.ts`** — ~35 URI generator functions (Reality, Hy2, XHTTP, CDN-WS, Finalmask, etc.)
- **`constants.ts`** — CF_CLEAN_IPS, FINALMASK ports, ISP fragments, MUX settings, WHITELISTED_HOSTS
- **`types.ts`** — TypeScript interfaces (Server, Env, User, protocol configs)
- **`utils.ts`** — UUID validation, ISP detection, sorting helpers
- **`kv.ts`** — KV storage operations (users, health, probes, overrides)
- **`probe.ts`** — Probe script generator

`worker.js` and `core-worker.js` are **generated** by `npm run build` (esbuild). Never edit them.

- **Key endpoints**: `/health`, `/sub/:uuid`, `/mtproto/:uuid`, `/admin/users`, `/probe`
- **Account tiers**: `premium` (all protocols/servers), `free` (first N servers), `limited` (CDN-only)

## Conventions

- **TypeScript first**: Always edit `tools/smart-sub/src/*.ts` files — NEVER edit `worker.js` or `core-worker.js` directly (they are generated by esbuild)
- **Build before deploy**: Run `npm run build` after changing src/ to regenerate `worker.js` + `core-worker.js`
- **Placeholder format**: Use `<PLACEHOLDER>` syntax in docs for secrets (e.g., `<SERVER_IP>`, `<UUID>`)
- **Deploy scripts**: Follow the pattern in existing `deploy-*.sh` files — read from vars.env, install, configure, print results
- **Commit messages**: `feat:`, `fix:`, `docs:`, `infra:`, `chore:` prefixes
- **Branch naming**: `feature/`, `fix/`, `docs/`, `infra/`, `research/` prefixes
- **Security**: NEVER hardcode real credentials — `vars.env` is gitignored

## Common Tasks

### Test worker locally

```bash
cd tools/smart-sub && npx wrangler dev worker.js --port 8787
curl http://localhost:8787/health | python3 -m json.tool
```

### Deploy server configuration

```bash
# Full server setup (first time)
ansible-playbook infra/ansible/playbooks/site.yml -i infra/ansible/inventory/hosts.yml

# Protocol-only update (no system changes)
ansible-playbook infra/ansible/playbooks/protocols.yml -i infra/ansible/inventory/hosts.yml

# Upgrade Docker images
ansible-playbook infra/ansible/playbooks/upgrade.yml -i infra/ansible/inventory/hosts.yml

# Or push to main — GitHub Actions deploys automatically when infra/ansible/ changes
```

### Deploy worker to production

```bash
# Option A: npm script (runs tests first)
cd tools/smart-sub && npm run deploy

# Option B: manual
cd tools/smart-sub
mkdir -p /tmp/vpn-sub-deploy && cp worker.js /tmp/vpn-sub-deploy/_worker.js
npx wrangler pages deploy /tmp/vpn-sub-deploy --project-name your-pages-project --commit-dirty=true

# Option C: push to main — GitHub Actions auto-deploys if worker.js changed
git push origin main
```

### Deploy backup sub to Vercel

```bash
cd tools/smart-sub && npm run deploy:backup
# or manually:
npm run build && cd tools/backup-sub && vercel deploy --prod --yes
```

### Verify production

```bash
curl https://sub.example.com/health | python3 -m json.tool
```

### Add a new protocol

1. Add TypeScript interface for the protocol config in `src/types.ts`
2. Add a `generateNewProtocolURI(server, uuid)` function in `src/generators.ts`
3. Add protocol config to server definitions in `config/servers.yaml`
4. Update `src/config.ts` to read the new protocol field from env/config
5. Call the generator in the subscription builder loop in `src/index.ts`
6. Run `npm run build` to regenerate `worker.js`
7. Test with `npx wrangler dev worker.js --port 8787`

### Add a new server

1. Add server entry to `config/servers.yaml`
2. Run `npm run validate:config` to check schema
3. Run `npm run docs:generate` to update markdown tables
4. Add server to `infra/ansible/inventory/hosts.yml`
5. Create `infra/ansible/inventory/group_vars/<server>.yml` with protocol flags
6. Update `vars.env.example` with new server variables

## What NOT to Do

- Don't commit `vars.env` or any file with real secrets
- Don't modify USERS/UUID section in config.ts without admin approval
- Don't edit `worker.js` or `core-worker.js` directly — edit TypeScript source in `src/` and run `npm run build`
- Don't push directly to `main` — use feature branches and PRs
- Don't deploy to production without testing locally first
- Don't change server IPs or CDN domains without coordinating with admin

## Documentation Sync

Config files in `config/` are the single source of truth for server topology, CDN settings, ISP tuning, and protocol defaults. Generated docs (markdown tables between `<!-- BEGIN GENERATED -->` markers) are updated by running:

```bash
npm run docs:generate    # Updates multi-server.md, README.md from config/*.yaml
npm run validate:config  # Validates config/*.yaml against JSON schemas
```

CI enforces this: the `docs-freshness` job runs `docs:generate` then checks `git diff --exit-code`.

### When changing worker source (src/)

- Run `npm run build` to regenerate `worker.js` and `core-worker.js`
- If adding an endpoint: update `docs/api.md` and `docs/openapi.yaml`

### When adding/removing a server

- Update `config/servers.yaml` (source of truth)
- Run `npm run docs:generate` to update all markdown tables
- Update cost figures in README.md intro text

### When changing CDN/relay infrastructure

- Update `config/cdn.yaml` (source of truth)
- Run `npm run docs:generate`
